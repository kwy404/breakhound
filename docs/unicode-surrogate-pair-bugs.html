Unicode surrogate pair bugs: why emoji get split in JavaScript

JavaScript strings are sequences of UTF-16 code units. Characters outside the Basic Multilingual Plane, including most emoji, take two code units called a surrogate pair. length, slice, substr and charAt count code units, so cutting at the wrong index leaves half a character behind: a lone surrogate that renders as a replacement box and breaks JSON and URL encoding.

split.ts
const s = "hi \u{1F44B}";s.length;              // 5, not 4s.slice(0, 4);         // "hi \uD83D" lone surrogate[...s].slice(0, 4).join(""); // safe: iterates code points

Real bugs

This bug class was fixed in google/budoux#1411 and microsoft/vscode-js-debug#2423, both maintained by teams that know Unicode well. It is easy to miss because tests rarely include emoji at the cut point.

How breakhound catches it

For every string parameter breakhound feeds emoji, flags, skin tone sequences and combining marks at many positions, then checks each string in the output with isWellFormed. A lone surrogate is reported as lone surrogate in output, with the shortest input that reproduces it.

terminal
npx breakhound ./my-string-lib

How to fix it

  • Iterate with for...of or spread to work on code points.
  • Use Intl.Segmenter or graphemely when you need user perceived characters.
  • Use String.prototype.toWellFormed as a last line of defense.

FAQ

What is a lone surrogate?
Half of a UTF-16 surrogate pair without its partner. It is not a valid character and breaks encodeURIComponent and many serializers.
Is code point slicing enough?
It avoids lone surrogates, but grapheme clusters such as flags and family emoji can still be split. Use Intl.Segmenter for those.
