How it sniffs

1. Read the types

Loads the package's TypeScript declarations to learn what each exported function accepts.

2. Generate edge cases

Builds inputs per parameter type from edgegoat: DST, time zones, emoji, -0, NaN, dates before 1970.

3. Run in isolation

Every call runs in a child process with a timeout, under several TZ values.

4. Check invariants

Reports violations with a minimal reproduction and a Vitest test you can commit.

Gate your CI

Use --fail-on to break the build on high severity findings and --json to keep the report.

.github/workflows/breakhound.yml
name: breakhoundon: [push, pull_request]jobs:  sniff:    runs-on: ubuntu-latest    steps:      - uses: actions/checkout@v4      - uses: actions/setup-node@v4        with: { node-version: 20 }      - run: npm ci --ignore-scripts      - run: npx breakhound . --fail-on high

Safety first

breakhound executes the code it scans. Run it on code you trust or inside a container. Installs from npm use --ignore-scripts, and each call runs in an isolated child process with a timeout.

FAQ

Run npx breakhound with a package name or a path. It reads the TypeScript types, generates edge case inputs and reports invariant violations, each with a minimal reproduction and a Vitest test.
Property based testing asks you to write the properties and generators. breakhound ships a fixed set of invariants and derives generators from the type signatures, so it works on code you have never read.
It executes the package code, so scan untrusted packages inside a container. Installs use the ignore scripts flag and every call runs in a child process with a timeout.
It works best with type declarations, bundled or from DefinitelyTyped. Without them it falls back to generic inputs.
