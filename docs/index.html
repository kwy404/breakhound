Find bugs in any JavaScript library automatically

Eight oracles

The bugs it sniffs out

Each oracle is an invariant that almost every library should keep. breakhound checks all eight on every exported function, with no configuration.

Split emoji

lone-surrogate-output

A string result contains half of a surrogate pair, so an emoji or astral character is cut in two.

truncate('\u{1F600}', 1) -> '\ud83d'

Time zone dependence

timezone-dependent

The same call returns different results when only the host TZ changes.

TZ=UTC yearLabel(0) -> '1970' TZ=New_York yearLabel(0) -> '1969'

Crash on valid input

unexpected-crash

A value the types allow, like an empty string, throws a TypeError.

initials('') -> throws TypeError

NaN leak

nan-leak

Finite numbers go in, NaN comes out where a real number was expected.

average([0]) -> NaN

Broken roundtrip

roundtrip

Partners such as encodeX and decodeX do not give the input back.

decodeBase(encodeBase('_')) -> ' '

Not idempotent

not-idempotent

Normalizing twice gives a different result than normalizing once.

slugify('x y') -> 'x_y' slugify(slugify('x y')) -> 'x-y'

Lost minus sign

negative-zero-sign

Values between -1 and 0 are formatted as if they were positive.

formatFixed(-0.5) -> '0.50'

Nondeterminism

nondeterministic

Same call, same input, different result, from hidden state or clocks.

label('a') -> 'a' label('a') -> 'A'
How it works

From package name to failing test in four steps

Everything below happens inside one command. You keep only the part you care about: the tests.

  1. Read the types

    breakhound installs the package with --ignore-scripts or opens your folder, then reads its TypeScript declarations to learn every exported function and parameter.

  2. Generate inputs

    Each parameter gets values from edgegoat: DST transitions, dates before 1970, emoji, lone surrogates, -0, NaN. Callbacks are generated too.

  3. Run in isolation

    Calls run in a child process with a timeout, repeated under several TZ values, with a fixed seed so every run is reproducible.

  4. Check and report

    Eight oracles judge the results. Each finding comes with a severity, a minimal reproduction and a Vitest test.

FAQ

Questions

Run npx breakhound with a package name or a path. breakhound reads the TypeScript types to learn what each exported function accepts, feeds it edge case inputs, and reports calls that break invariants such as roundtrips, idempotence, sign preservation or time zone independence. You do not need to write any test first.

Tools such as fast-check ask you to write the properties and generators yourself. breakhound ships the properties, a fixed set of invariants that hold for most libraries, and derives the generators from the type signatures, so it works on code you have never read. When it finds something, it hands you a regular Vitest test you can keep.

breakhound executes the code it scans, so treat it like running the package's own test suite. Installs use --ignore-scripts and every call runs in a child process with a timeout, which is isolation for robustness, not a security sandbox. Scan untrusted packages inside a container or a disposable VM.

It works best with TypeScript declarations, either bundled .d.ts files or DefinitelyTyped. Without types it falls back to a smaller set of generic inputs.

Some invariants, such as time zone dependence, can be intentional for a given function. Every finding has a confidence level and a minimal reproduction so you can judge it in seconds, and --rules, --only and --exclude let you narrow the hunt.

Yes. Inputs come from a seeded generator (seed 42 by default, change it with --seed), the call budget is fixed with --max-calls, and each run is saved to .breakhound/last-run.jsonl and .breakhound/report.json unless you pass --no-save.
