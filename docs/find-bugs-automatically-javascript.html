How to find bugs automatically in a JavaScript library

Most libraries have tests for the inputs their authors thought about. The bugs live in the inputs nobody thought about: an emoji at the cut point, a user in Tokyo, a value of -0.5. breakhound finds those without you writing a single test.

Step 1: run it

terminal
# a package from npmnpx breakhound some-package # or a local foldernpx breakhound ./my-lib

Step 2: what happens

breakhound reads the TypeScript declarations to learn each parameter type. For a string it tries emoji, combining marks and lone surrogates. For a Date it tries DST transitions, year boundaries and dates before 1970. For a number it tries -0, NaN, values between -1 and 0 and huge values. These come from the edgegoat catalog.

Each call runs in an isolated child process with a timeout, under several TZ values, and the results are checked against invariants: no lone surrogates, no time zone dependence, no crash on valid input, no NaN leak, working roundtrips, idempotent normalization, preserved sign and determinism.

Step 3: keep the test

Every finding comes with a minimal reproduction and a Vitest test. Example output, illustrative only:

truncate.breakhound.test.ts
import { test, expect } from "vitest";import { truncate } from "example-strings"; // breakhound: lone surrogate in outputtest("truncate never splits an emoji", () => {  const out = truncate("hi \u{1F44B} there", 4);  expect(out.isWellFormed()).toBe(true);});

Step 4: gate CI

terminal
npx breakhound . --fail-on high --json > findings.json

breakhound executes the code it scans, so run it on code you trust or inside a container. Installs use --ignore-scripts.

FAQ

Do I need to write tests first?
No. breakhound derives inputs from type signatures and checks built in invariants.
How is this different from fuzzing?
Coverage guided fuzzers such as Jazzer.js mutate inputs to find crashes. breakhound uses typed edge cases and checks semantic invariants such as time zone independence and sign preservation.
